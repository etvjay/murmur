Offline payments don't need more promises. They need a confirmed transaction.

Pilots for offline money are run by issuers. Offline messengers carry no money. Murmur carries a real shielded Zcash transaction and a sealed note between devices, and the payment confirms on chain when someone reconnects.

Built with the network cut.

The payer's wallet creates, proves and signs a shielded transaction with no connection at all. A lookup of the wallet server fails first, by design. Only the final raw transaction leaves the device, never the partly built file that can hold viewing keys.

See the offline log

Carried device to device, sealed.

The transaction and a sealed note pass to nearby devices, each forwarding with a hop limit, duplicate drop and retransmission. Devices in between pass the note along but cannot open it. The transaction stays shielded, so it reveals nothing about who paid whom.

Try the simulation

Whoever reconnects first broadcasts.

The first device that reaches the internet submits the transaction, once. Every other copy is dropped as a duplicate. The merchant opens the sealed receipt and sees the payment confirm.

See the broadcast

Proven on the testnet, not on slides.

Over a limit, the wallet is never asked to sign. The policy bounds double-spend risk; it does not remove it.

              

            

            

              
No payment signs past the cap.

              
The spend policy runs before anything is built. A payment over the per-payment or offline total is refused with the reason, and the wallet never runs.

              See the limits
            

          

        

        

          
Caps you choose.
Per-payment and offline totals, plus an optional recipient list.

          
Sealed to one recipient.
X25519 and ChaCha20-Poly1305 with no recipient tag, so relays cannot tell whom a note is for.

          
Only the final transaction travels.
The partly built file can hold viewing keys and note details, so it never leaves the payer.

          
Testnet only.
No mainnet keys or funds. Every run is logged in the evidence folder.

Run A: built with the network cut

        
The build ran in a network namespace with no connection. A lookup of the wallet server failed there first, as required. Then every step of the transaction build succeeded.

  • Raw transaction20,986 bytes, unified-address recipient
  • BroadcastNo. This run stops before broadcast by design.
  • Log folderevidence/03-acceptance-a

        
Run B: across the carrier and onto the chain

        
A payer process built the transaction and sent it with a sealed receipt. A separate gateway process received both, broadcast the transaction once and sent back a sealed acknowledgement. Both ran on one machine over UDP loopback, so this run did not use a radio.
