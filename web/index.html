Offline private payments and messages

Anyone can claim a payment works offline.

Murmur shows one that confirmed.

Offline payments don't need another promise. They need a confirmed transaction.

Plenty of projects say private money can move without a network. Murmur carries a real shielded Zcash transaction and a sealed note from device to device, and the payment confirms on chain when someone reconnects. Every number on this page comes from a log in the project's evidence folder.

What we have not proven

A payer can still double-spend before the transaction is broadcast, and the spend policy only limits the loss. Relays still see packet size and timing. The test between two real devices, relaying through more than two hops, and authenticated receipts are not done yet.

  • Not a wallet
  • Not a new currency
  • Not trustless settlement
  • Not anonymous routing

What an observer can learn

        
  • Packet sizes, timing, and which neighbor sent what.
  • That a shielded transaction exists. Not the payer, the recipient or the amount.
  • A relay can drop or delay a packet. Redundant paths and retransmission help; nothing guarantees delivery.

      
What we will not claim

        
  • Trustless offline settlement. A payer can double-spend before broadcast; the spend policy only limits the exposure.
  • Anonymous routing or hop-level privacy.
  • Real radio range or multi-hop results.

      
Next

        
  • Authenticated receipts.
  • The note carried in the transaction's encrypted memo.
  • The two-device test, then a third device for a real relay.

      
Lessons from the real run

        
  • Signing needs the proven transaction file, because proving writes the key material signing requires.
  • A transaction to a unified address is about 21 KB; to a Sapling address about 5 KB. Larger means more packets and more loss sensitivity.
  • The carrier relays only the final raw transaction, never the partially built one, which can contain viewing keys and note details.
